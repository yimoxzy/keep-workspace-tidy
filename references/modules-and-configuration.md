# 模块与配置示例

## 模块归属和依赖方向

- `task_service` 和 `report_service` 都要解释同一组任务状态时，把状态及其纯判断放在任务领域已有的模块，两边都引用它。共享模块不反向导入服务，也不用临时导入规避循环。两边的规则若会独立变化，各自保留。
- `main.py` 负责解析参数、接线和返回退出码。任务状态流转放进现有业务模块。职责独立且便于测试时才拆文件，紧密相关的小段逻辑可以保留在一起。避免按行数、函数数量或固定分层模板拆文件。测试辅助留在测试侧。Python 项目已有 `__init__.py` 导出约定时，按需公开跨模块调用所需的接口。

## 固定契约和可调参数

- 协议规定任务成功状态是 `completed` 时，用 `TaskStatus.COMPLETED` 表达。运维可以调整的请求超时走既有配置。只在一处使用且含义清楚的固定值留在调用处，含义不直观时用局部命名常量。
- `if user_id == 12345` 或 `if status == "special_case"` 若只是在照顾某条记录，先找业务契约或现有能力标记。按账号开放功能可以检查已有权限。协议若明确规定特殊状态，使用已定义的状态枚举，并验证该分支及常规行为。把临时 ID 改成命名常量仍会保留同一条特例。
