# Keep Workspace Tidy

一个面向 Codex 的工程 Skill。用于改代码、排障和评审，要求主动指出有证据的设计隐患，用最小改动解决根因，并验证用户能走完主流程和关键异常流程。日常改动默认原地编辑，临时文件和交付物各用已有位置。

## 使用

把 `keep-workspace-tidy` 目录放进 `~/.agents/skills/`，或放进目标项目的 `.agents/skills/`。在 Codex 中明确调用。

```text
$keep-workspace-tidy 审查任务执行链路并修复卡在运行中的问题。指出框架或 Agent 设计里有证据的隐患，验证正常完成和取消后的状态。
```

## 遇到这些情况时

| 情况 | 处理方式 |
| --- | --- |
| 工具派发成功，界面却显示任务完成 | 对照实际工具回执和持久化状态，指出错误发生在哪一级，修复后从正常入口验证终态。 |
| 主数据源超时，旧代码会读失效缓存 | 保留超时和失败状态。若有可用的只读缓存方案，先说明时效和缺失能力，由用户决定是否允许降级。 |
| 两个版本支持不同协议 | 在入口按明确版本选择适配器。核对未知版本的结果，避免依赖异常去试其他实现。 |
| 修一个局部缺陷 | 改动限于相关代码，只运行覆盖该行为的定向测试，汇报实际命令和结果。 |
| 普通修改顺手留了 `.bak` 和多份报告 | 原地改文件并检查 diff。从本轮产物中清理无用副本，生产回滚材料按项目规则保存。 |

工程部分参考 [yeahjack/avoid-overkill](https://github.com/yeahjack/avoid-overkill) 的范围控制、根因修复与行为验收。本 Skill 进一步明确了主动反馈设计风险、运行时回退确认和工作区收尾方式。
